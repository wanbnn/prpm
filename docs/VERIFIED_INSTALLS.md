# Hash-verified installs

PRPM lockfiles record the artifact hashes reported by pip during dependency resolution. Those hashes can be enforced during installation instead of remaining passive metadata.

## Strict CI mode

Use a frozen lockfile together with hash verification:

```bash
PRPM_VERIFY_HASHES=1 prpm install --frozen
```

On PowerShell:

```powershell
$env:PRPM_VERIFY_HASHES = "1"
prpm install --frozen
```

PRPM converts the selected lockfile entries into a temporary requirements file and invokes pip with `--require-hashes`. pip therefore rejects a downloaded artifact whose digest is not present in `prpm.lock`.

This adds a second guarantee on top of `--frozen`:

- `--frozen` guarantees that the manifest and locked dependency graph match;
- `PRPM_VERIFY_HASHES=1` guarantees that installed artifacts match the hashes recorded for that graph.

Python integrations can request the same behavior explicitly:

```python
PackageManager(manifest).install(frozen=True, verify_hashes=True)
```

## Compatibility and platform scope

Hash verification is opt-in. Existing installs keep their current behavior.

A lock generated by older PRPM versions may store bare SHA-256 digests; PRPM normalizes those values automatically. Newly generated locks store algorithm-prefixed hashes such as `sha256:...`.

The current lock format records artifacts selected by pip on the platform where resolution occurred. A strict frozen install on another operating system or Python ABI may require a different wheel and can therefore fail hash verification. In that case, regenerate the lock on the target platform or use the normal frozen mode without hash enforcement.

Packages whose resolver report does not contain an artifact hash are rejected before pip runs in verified mode. PRPM does not silently downgrade a requested verified install.
