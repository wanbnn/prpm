# Frozen and hash-verified installs

PRPM lockfiles record the exact dependency graph selected by pip. Newly generated lockfiles also record the PEP 508 marker environment used during resolution, including Python implementation/version and platform variables that can change marker evaluation.

## Environment-safe frozen mode

Use a frozen lockfile in CI or deployments where dependency resolution must not change:

```bash
prpm install --frozen
```

Frozen mode now validates two things before installation:

- the manifest dependencies still match the lockfile content hash;
- the current PEP 508 marker environment matches the environment that produced the lockfile.

This prevents a lock resolved on one Python/platform combination from being silently reused where environment markers could select a different dependency graph. If the environment does not match, regenerate the lock with a normal `prpm install` on the target environment.

Lockfiles created before environment fingerprints were introduced are intentionally considered stale for `--frozen`. A normal `prpm install` upgrades them automatically by resolving and writing a new environment-bound lock.

## Strict artifact verification

PRPM lockfiles also record the artifact hashes reported by pip during dependency resolution. Those hashes can be enforced during installation instead of remaining passive metadata.

Use a frozen lockfile together with hash verification:

```bash
PRPM_VERIFY_HASHES=1 prpm install --frozen
```

On PowerShell:

```powershell
$env:PRPM_VERIFY_HASHES = "1"
prpm install --frozen
```

PRPM converts the selected lockfile entries into a temporary requirements file and invokes pip with `--require-hashes`. pip therefore rejects a downloaded artifact whose digest is not present in `prpm.lock`.

This adds a third guarantee:

- `--frozen` validates the manifest against the locked dependency graph;
- `--frozen` validates the current marker environment against the resolution environment;
- `PRPM_VERIFY_HASHES=1` guarantees that installed artifacts match the hashes recorded for that graph.

Python integrations can request the same behavior explicitly:

```python
PackageManager(manifest).install(frozen=True, verify_hashes=True)
```

## Compatibility and platform scope

Hash verification remains opt-in. Existing non-frozen installs keep their normal resolve → lock → install flow and automatically refresh stale environment fingerprints.

A lock generated by older PRPM versions may store bare SHA-256 digests; PRPM normalizes those values automatically after the lock has been regenerated for the current environment. Newly generated locks store algorithm-prefixed hashes such as `sha256:...`.

The current lock format records artifacts selected by pip on the environment where resolution occurred. Cross-platform or cross-Python frozen installs are rejected before pip runs instead of risking a graph selected under incompatible marker values.

Packages whose resolver report does not contain an artifact hash are rejected before pip runs in verified mode. PRPM does not silently downgrade a requested verified install.
